# The PubSys Guide

PubSys is the small publishing system Paul Ingraham wrote for his websites. You write each post as a plain text file; PubSys turns the files into finished web pages. This guide describes PubSys as it runs on the family blogs (Ephemeral Treasures, Diversions, and Writerly). It's written so a beginner can follow it, but its main reader is Claude, who uses it to help the people who write these sites.

Everything here was checked against the code and against real test builds (September 2026). Where this guide and the code disagree, the code wins, and the guide needs fixing.

> **This file is a copy.** The original lives in Paul's painscience project (`painscience/incs/PUBSYS-GUIDE.md`) and is copied into each blog's `incs/` folder along with the rest of the PubSys code. Never edit a copy: the next code update overwrites it.

## 1. The folders

| Folder or file | What it is | Edit it? |
|---|---|---|
| `posts/` | The post source files, one per post. This is where writing happens. | Yes |
| `html/imgs/` | The pictures used in posts. | Yes (add images) |
| `html/` (everything else) | The finished website, rebuilt by every build. | **No.** Changes are overwritten or deleted. |
| `guts/` | The site's settings and design: page templates, the home page, the stylesheet, the tag list, redirects. | Carefully |
| `incs/` | The PubSys program code, shared with Paul's other sites and replaced by updates. | **No** |
| `make-site.php` | The build script. | **No** |
| `.cache/` | The build's memory of unchanged posts. | No; ignore it |
| `===CURRENT-POST-PREVIEW.html` | A preview of the *newest* post (by date), with a table of its settings on top. | No (generated) |

**The design in brief.** The finished site is deliberately simple: plain HTML pages with no database and no programs running on the web server, so it's fast and there's nothing to hack. Every page sits directly in `html/` (there are no subfolders of pages), and every page is built from the same post template. The stylesheet is copied into each page at build time.

Some files in `guts/` are also generated by the build and should be left alone: `posts-all-index-links.html`, `posts-links.md`, `posts-matrix.tsv`, `tags.used.txt`, and the `tags-*.json` and `tags-qrg-*.txt` files.

## 2. Building and previewing

A **build** reads every post file and rewrites the website in `html/`. Nothing you change in `posts/` shows up until you build.

- **To build:** open `http://SITE.test/make-site.php` in a browser, where SITE is the site's local name (`ephemeral`, `diversions`, `writerly`). Each site folder has a `MAKE.webloc` bookmark that does this. From a terminal, `curl -s http://SITE.test/make-site.php` runs the same build and prints the same page as HTML.
- **Quick vs full:** a normal build is *quick*: it only re-reads post files that changed since the last build. Add `?full` (`make-site.php?full`) to re-read everything. Use a full build when a change doesn't seem to take effect.
- **To preview a post:** open `http://SITE.test/html/ADDRESS.html`, where ADDRESS is the post's page address (§5). The build log links every page it writes. Browsers cache pages, so reload after building.
- **The local web server** (Apache on the Mac) has to be running for any of this to work. If the build page won't load at all, the problem is the server, not PubSys.

### Reading the build page

The build page is a numbered log of what the build did ("Making post file …", "Skipping locked post …"), followed by a big table of every post. Problems show up in two places:

- **ABORT!** in large type means the build stopped partway. Nothing after that point was built. The message names the post and the problem; the most common cause is a missing image (§7). Fix it and build again.
- **An error panel** at the very bottom ("2 errors on this page (0 failures, 2 warnings, 0 notices)") lists problems the build noticed but survived. Failures are serious; warnings usually mean something in a post will look wrong (unbalanced HTML, a mistyped shorthand); notices are informational.

## 3. Post files

### Filenames

A post's filename starts with its date, then **one space**, then any name you like:

```
2026-05-10 Prestwick crash part 6.html
```

- The date (year-month-day) is the post's publication date. It's shown on the page and sets the post's order on the site. The year must start with 20.
- Two posts on the same day can get a letter after the date to set their order: `2026-05-10a …`, `2026-05-10b …`. A post with no letter counts as the day's first, so only the later ones need one.
- The name after the date is only for you. It doesn't affect the page title or address.
- The extension doesn't matter. `.html`, `.md`, and `.txt` files are all read the same way: as Markdown, with HTML allowed (§6).
- **A file whose name doesn't start with a date is ignored by the build.** That's the simplest way to keep a draft in `posts/` without it appearing anywhere.
- **Don't put the capitalized word `POSTS` in the filename of an ordinary post.** Any filename containing `POSTS` is read as a micropost file (§11), and an ordinary post in one silently disappears. Image files in `posts/` are special too (§11).

### Inside the file

```
The title of the post
tags: stamps, aviation, WWII
description: A one-sentence summary for search engines and link previews.
harbour-1946.jpg
*****
The body of the post starts here. Everything from this line down
is the content of the page.

----------
Notes to self down here are never published.
```

- **Line 1 is the title.** Always.
- **The header** is every line from the title down to a line of asterisks (`*****`). It holds settings for the post, one per line (§4).
- **The asterisk line** ends the header. Any line containing five or more asterisks in a row counts. If a post has no asterisk line, the whole file is treated as header and the post has **no body**.
- **The body** is everything after the asterisk line.
- **A line of ten or more hyphens** (`----------`) ends the post. Everything below it is ignored, which makes it a good place for private notes. (A Markdown divider line of three hyphens, `---`, is fine.)
- **Lines starting with `//`** are dropped from the post anywhere in the file, so they work as private one-line comments.
- **A line containing five asterisks inside the body is silently dropped**, because it looks like a second header line.

## 4. Header settings

Each header line is either `name: value` or a single word. Capitalization of setting names doesn't matter: `Tags: stamps` and `tags: stamps` both work. Lines the build doesn't recognize are ignored without any warning, so a misspelled setting simply does nothing.

| Setting | Example | What it does |
|---|---|---|
| `tags` | `tags: stamps, aviation` | The post's tags (§10). Also accepts `tagged` and `keywords`. |
| `description` | `description: How a 1948 crash…` | The summary search engines and link previews show. Without one, PubSys uses the first ~115 characters of the post. Also accepts `summary`. |
| an image filename | `harbour-1946.jpg` | The picture shown when someone shares the post on social media. The file must be in `html/imgs/`. |
| `subtitle` | `subtitle` | Splits the title at its first colon, question mark, exclamation mark, ellipsis (…), or em dash (—) into a main title and a smaller subtitle. **This also shortens the page address to the main title** (§5). |
| `slug` | `slug: Prestwick Crash 6` | Sets the page address (§5). Also accepts `filename:`, which is the name the family blogs use. It doesn't rename the source file. |
| `draft` | `draft` | Builds the page with a red "DRAFT — NOT FOR PUBLICATION" banner and leaves it off the home page, feed, and sitemap. **The page is still built, and it goes live at its address when the site is published.** It's unlisted, not private. Also accepts `preview`. |
| `lock` | `lock` | Also accepts `ignore`. Doesn't build the post at all. **If the page already exists, the build deletes it** from `html/`, so `lock` takes a post off the site. |
| `link` | `link: https://example.com/story` | A "featured link": the post's title links to that address (marked with ∞), and a "Featured link" line appears at the end of the post. |
| `hidelink` | `hidelink: https://…` | Like `link`, but without the line at the end. |
| `priority` | `priority: 8`, or just `8` | How important the post is, from 1 to 10, as a hint to search engines (via the sitemap). Ordinary posts default to 7. 9 or 10 also adds a "best of" tag. |

Some other settings exist in the code but only matter on PainScience.com.

A header line that is only a web address does nothing; featured links must be labelled with `link:`.

## 5. Page addresses

Every post gets a page address, its **slug**: the part of the web address before `.html`. PubSys makes it from the title by lowercasing it, turning spaces into hyphens, dropping most punctuation, turning `&` into "and", and dropping a leading "The", "A", or "An":

| Title | Address |
|---|---|
| The Lindbergh Puzzle, Part 2 | `lindbergh-puzzle-part-2.html` |
| What’s in a name? Stamps & covers | `whats-in-a-name-stamps-and-covers.html` |
| Christmas tragedy at Prestwick (Part 6) | `christmas-tragedy-at-prestwick-(part-6).html` |

A `slug:` (or `filename:`) setting overrides the title and is converted the same way, so `filename: Prestwick Crash 6` gives `prestwick-crash-6.html`. Without one, the `subtitle` setting uses only the part of the title before the divider. **The address never comes from the source file's name**, so the two often differ.

**Changing a title changes the address.** On the next build the old page is deleted and a new one appears under the new address, so links to the old address break, including links from other posts and from elsewhere on the web. To retitle a post that's already published, keep its address with a `slug:` or `filename:` setting that produces the old address. For a page that must move, add a redirect to `guts/_redirects`, one per line: `/old-address.html /new-address.html 301`.

**Linking to another post:** use its address, with no folder: `[the previous part](lindbergh-puzzle-part-1.html)` or `<a href="lindbergh-puzzle-part-1.html">`. The build log and the big post table on the build page show every post's address.

## 6. Writing the body: Markdown and HTML

The body is written in **Markdown**, a set of simple typing conventions that become formatting. PubSys uses a version called PHP Markdown Extra. **HTML can be mixed in freely**, and most trouble comes from how the two mix.

### Markdown basics

| Type this | To get |
|---|---|
| A blank line between paragraphs | Separate paragraphs |
| `*italic*` and `**bold**` | *italic* and **bold** |
| `## A heading` (or `###` for a smaller one) | Section headings. Don't use a single `#`; the page title is already the top heading. |
| Lines starting with `- ` or `1. ` | Bulleted or numbered lists |
| `> ` at the start of lines | An indented quotation |
| `[link text](https://example.com)` | A link |
| `---` (or `***`) on a line by itself, with a blank line above it | A horizontal divider line (without the blank line, `---` turns the text above into a heading). Five or more asterisks is something else entirely (§3). |
| `Text.[^1]` … `[^1]: The note.` | A numbered footnote, listed at the end of the post |

Markdown Extra also makes simple tables:

```
| Year | Stamps |
|------|--------|
| 1946 | 12     |
```

PubSys doesn't change quotation marks, so curly quotes stay curly and straight quotes stay straight.

### Rules for mixing in HTML

1. **Start block-level HTML on its own line, with a blank line before and after it.** Block-level elements include `<div>`, `<p>`, `<table>`, `<blockquote>`, `<ul>`, `<ol>`, and headings.
2. **Markdown isn't processed inside block-level HTML** unless the opening tag says `markdown="1"`. In `<div class="sidebar">*Note*</div>` the asterisks show up literally; `<div class="sidebar" markdown="1">` makes them italics.
3. **Every opening block tag needs its closing tag** (`<p>` … `</p>`, `<div>` … `</div>`). A missing one produces the build warning "unbalanced HTML … Markdown may mangle this post". It can also produce visible junk: in testing, one unclosed `<p>` put a stray "p>" into the text of the page.
4. **Inline HTML works inside ordinary paragraphs:** `<em>`, `<strong>`, `<a>`, `<span>`, `<br>`, `<img>`, `<sup>`.
5. **Only real HTML elements do anything.** A made-up tag like `<bigger>` is ignored by browsers. Old elements like `<font>` and `<center>` still work but are outdated; for new work, prefer the classes in §9.

### Other things to know

- **Backslashes vanish.** `C:\Users` comes out as `C:Users`. Write a backslash as `&#92;` if you really need one.
- **Extra spaces collapse** into one, as they always do in web pages. For a line break without a new paragraph, use `<br>`. (Two spaces at the end of a line also make a line break, Markdown's own method, but they're invisible and easily lost.)
- **`<?php … ?>` in a post runs as program code** during the build. Don't use it unless Paul has set it up for a reason.
- **HTML comments** (`<!-- like this -->`) don't show on the page, but they're in the page's public source, so don't put anything private in them. For private notes, use `//` lines or the area below `----------` (§3). (Image lines inside comments are still checked for their files; see §7.)

## 7. Images

Put image files in `html/imgs/`, then refer to them by filename. The best filenames use only letters, numbers, hyphens, and underscores: `harbour-1946.jpg`, not `Harbour 1946.JPG`. **Match capitalization exactly:** the Mac forgives `Photo.jpg` vs `photo.jpg`, so the build and the local preview look fine, but on the live site the picture is missing. (Checked on the live Diversions site in September 2026.)

### The PubSys image shortcut

Put the filename at the start of a line by itself, optionally followed by options separated by three hyphens (`---`) or tabs (any number of them):

```
harbour-1946.jpg---left---The harbour at Halifax in 1946, from a postcard.
```

The options:

- **`left`, `right`, `centre`** (or `center`): placement. `right` is the default, with the text wrapping around the picture. **Images wider than 380 pixels are always centred**, whatever you ask for.
- **`300px`**: displays the image 300 pixels wide; the height scales to match.
- **`shadow`** (or `ds`): a drop shadow.
- **Anything else** is the caption, whatever its length: `harbour-1946.jpg---left---My dog`. Captions can contain Markdown, such as italics and links. A misspelled option (`rigth`) therefore shows up as a caption.
- **`c|` followed by text** is also a caption, for the rare caption that would otherwise be read as an option: `c|shadow`.
- **`alt|` followed by text**: a description for people using screen readers.
- **`inline`**: places the image inside a paragraph (with the `<<…>>` form below) rather than as its own block.

The bare-line form only recognizes filenames made of letters, numbers, hyphens, and underscores. **A filename with spaces on a line by itself is printed as plain text.** For those, and anywhere else, use the double-angle-bracket form, which works in any position, including mid-sentence and for images in subfolders of `imgs/`:

```
<<Screen Shot 2014-08-20.jpg---c|The front of the cover>>
```

**Image lines are processed even inside HTML comments** (`<!-- … -->`). The picture stays hidden, but if its file is missing, the build still stops. To switch off an image line completely, put `//` at the start of it (§3).

**If the image file doesn't exist, the whole build stops** with "ABORT! … image file 'harbour-1946.jpg' not found". Check the filename's spelling and that the file is really in `html/imgs/`.

After one or more pictures placed `left` or `right`, a `!clear` line (§8) makes the following text start below them instead of beside them.

### Plain HTML images

`<img src="imgs/harbour-1946.jpg" width="400" alt="…">` also works (note `imgs/`, with no leading slash). There's no missing-file check, though: a mistyped name just shows a broken image, and there are no captions or placement options.

### Image sizes

Photos straight from a camera or scanner are often thousands of pixels wide and several megabytes, which makes pages slow. For the web, 800–1200 pixels wide is plenty for most pictures, and a few hundred kilobytes is typical. On a Mac, Preview's *Tools › Adjust Size…* resizes, or in a terminal: `sips -Z 1200 photo.jpg --out html/imgs/photo.jpg`.

## 8. PubSys shorthands

These are PubSys's own additions to Markdown.

**Shorthand lines**: an exclamation mark and a word on a line by itself, with blank lines around it:

| Line | Result |
|---|---|
| `!stars` (or `!3stars`) | A centred ★ ★ ★ divider |
| `!clear` (or `!clearall`) | Makes the following text start below any floated images |
| `!break` (or `!br`) | A little extra vertical space |
| `!sidebar` (or `!aside`, `!note`) | Turns **the next line** into a boxed sidebar paragraph |

`!sidebar` works with or without a blank line before the paragraph it applies to. It styles a single paragraph; for a sidebar with several paragraphs or a heading, use `<div class="sidebar" markdown="1">` (§9).

The alternative words (like `!3stars`) come from `incs/synonyms-pubsys-shorthands.txt`, and there are similar lists for header settings and image options. On the family blogs those files are shared code, replaced by every update, so new synonyms have to be added by Paul.

Nothing else may be on the shorthand's line, though trailing spaces don't matter. A mistyped shorthand (`!clearr`) is printed on the page as-is, and the build shows a warning.

**The bullet divider**: a line containing just `•` becomes a small, light centred divider, often used before a closing section. Watch out: a bullet at the *end* of any line also becomes a divider.

**Featured quotations**, in a Markdown quote:

```
> q This quotation gets special decorative styling.
>
> ~ The Person Who Said It
```

`> Q` (capital Q) gives larger type, meant for short quotes. A `~` at the start of a paragraph styles it as an attribution line, and the `~` itself disappears. That applies to *any* paragraph starting with `~`, inside a quotation or not. Two quotes in a row with just a blank line between them merge into one, so put something between them. Using `q` or `Q` adds a "quotes" tag to the post automatically.

**Marking the description**: instead of a `description:` setting, you can mark a passage of the body with `∂` (Option-D on a Mac). The symbols never show on the page. There are three ways:

- Around the passage: `Some text. ∂This becomes the description.∂ More text.`
- One `∂` at the end of the post's opening words: `This becomes the description. ∂ More text.`
- One `∂` anywhere inside an emphasized phrase: `*∂This becomes the description.*`

## 9. Styles

These CSS classes are available on every PubSys blog (from the shared stylesheet):

| Class | Use it like | Effect |
|---|---|---|
| `sidebar` | `<div class="sidebar" markdown="1">…</div>` | A boxed aside |
| `preamble` | `<p class="preamble">…</p>` | Smaller grey introductory text |
| `color_light_gray`, `color_med_gray`, `color_dark_gray` | `<span class="color_med_gray">…</span>` | Grey text |
| `ds` | `<img class="ds" …>` | A drop shadow on a plain HTML image |

Each site's own stylesheet, `guts/css-*.css`, can add more (for example, colour classes). Check it before inventing a class name; a class that isn't defined anywhere does nothing.

**YouTube videos:** paste this, replacing `VIDEO_ID` with the code from the video's address:

```
<div class="ytemb"><iframe class="ytemb" src="https://www.youtube.com/embed/VIDEO_ID" allowfullscreen></iframe></div>
```

Inline styles (`style="color: brown"`) work too, but they're harder to keep consistent.

## 10. Tags

- List tags in the header, separated by commas: `tags: stamps, aviation, WWII`. Capitalization, spacing, and simple plurals don't matter: `Stamp` matches `stamps`.
- **A tag the site hasn't seen before is added to the site's tag list** (`guts/tags-*.txt`) on the next build, and it **stays there** even after it's removed from the post. A typo in a tag makes a permanent stray tag, which has to be deleted from the tag list by hand.
- A tag starting with `#` (`#one-off`) is used for this post only and never added to the list.
- The tag list file can be edited: its top section explains how to add descriptions, synonyms, and parent tags. The build rewrites the file into a standard layout, so keep edits to that format.
- Tag pages (`tag-….html`) are only built for tags used on six or more posts.
- Some tags are added automatically: a size tag from the word count ("size S" to "size XL"), "link" for posts with a featured link, "quotes" for featured quotations, "av" for image posts.

## 11. Rarely used post types

Most posts are ordinary files as in §3. Two other types exist:

- **Micropost files**: a file whose name contains `POSTS` holds many short posts, one per line. Each line starts with a date and a space, then the title and text, separated by `---` or tabs: `2026-05-01 --- A short title --- The text of the post. --- tags: stamps`. A line whose text is under 50 characters is silently skipped. Instead of a separate title, a line can mark its title inside the text with `§` symbols: `2026-05-01 --- A post about §the title§ and more.` Inside the text, `………` starts a new paragraph, `>>>` a quotation, `•••` a bullet item, and `111.` a numbered item.
- **Image posts**: an image file placed in `posts/` with a dated name becomes a post of its own. Its name carries the title, caption, tags, and source, separated by `|`: `2026-05-01 Title | Caption | tags | source name | source-web-address.jpg`. Filenames can't contain `/`, so write the source's web address with `:` in its place (`example.com:photos:turtle`), and PubSys turns the colons back into slashes.

## 12. The rest of the site

- **Home page:** `guts/template-home-page.php`, hand-written HTML, is turned into `html/index.html` on every build. Edit the template, never `index.html`. It can include the automatic list of all posts (`posts-all-index-links.html`) or leave it out.
- **Post template:** `guts/template-post.php` is the page layout wrapped around every post: the header, the author line, the footer. A change there changes every page on the site, so edit carefully and check a few posts afterward.
- **Stylesheets:** `guts/css-*.css` is the site's own; `incs/css-pubsys.css` is shared code (don't edit it). Because the stylesheet is copied into every page, a stylesheet change shows up only after a build, and then on every page at once.
- **Settings:** `guts/settings-*.php` is a simple list of site facts (name, author, domain, email, logo) despite its `.php` name.
- **Error page and redirects:** `guts/404.html` and `guts/_redirects` are copied into `html/` on every build, so edit them in `guts/`.
- **Also generated each build:** the RSS feed (`html/feed-*.xml`, the 30 newest non-draft posts), the sitemap, and the tag pages.
- **Stray pages are deleted.** Every build deletes any `.html` file directly inside `html/` that isn't a current post, a tag page, or `index.html`. Don't put hand-made pages there: make them posts instead. Files in subfolders of `html/`, and files that don't end in `.html`, are left alone.

### Websites made of pages, not blogs

PubSys was built for blogs: a stream of dated posts, newest first, with an automatic list of them on the home page. It works just as well for a website of pages organized by topic, and that's how both Ephemeral Treasures and Diversions use it. In that style:

- **The automatic list is switched off** in the home page template (its `include('posts-all-index-links.html')` line is commented out). Visitors find pages through links written by hand: topical lists on the home page, hub pages that each gather the pages on one subject (hub pages are ordinary posts too), and navigation links between the parts of a series.
- **A new page can't be reached until something links to it.** Adding a page includes deciding where it should be linked from.
- **Nothing checks those links.** Changing a page's address (§5) or unpublishing it breaks every hand-made link to it, silently. Before doing either, search `posts/` and the home page template for the old address.
- **Dates still exist, but mostly as labels.** Every page needs one in its filename, and it's shown on the page. It also sets the order of the RSS feed, the sitemap, and tag pages, and it decides which page counts as "newest". Otherwise it can be any date that suits (all parts of a series sharing one, say), and changing it doesn't change the page's address.
- **`===CURRENT-POST-PREVIEW.html` shows the newest-dated page**, which usually isn't the one being worked on. Preview a page at its own address instead.

## 13. Troubleshooting

**A change doesn't show up.**
1. Was the right file edited? The source is in `posts/`; the page in `html/` is only the result.
2. Did the build run, and did it finish? Look for ABORT!
3. Reload the browser page; browsers keep old copies.
4. Does the filename start with a date and a space? Is the post `lock`ed?
5. Try a full build (`?full`).

**The formatting is broken.**
1. Look for an "unbalanced HTML" warning at the bottom of the build page.
2. Check that HTML blocks start on their own lines, with blank lines around them (§6).
3. Is Markdown inside a `<div>` without `markdown="1"`?
4. Is the text cut off? Look for a line of ten or more hyphens, or five or more asterisks.
5. Compare the source with what the build produced: open the page's file in `html/` and find the spot.

**The build stops with ABORT!** Read the message: it names the post and the problem. Usually it's a missing or misspelled image file.

**The build page is blank, or shows PHP errors about code files.** That's a problem with PubSys itself or with the Mac's web server, not with the writing. Paul needs to know.

### Checking a change (for Claude)

After an edit, build with `curl -s http://SITE.test/make-site.php` and check the output for "ABORT" and for the error panel's warnings. Then read the rendered page in `html/` around the changed spot and confirm the HTML is what was intended. Fix display problems in the post source, never in `html/`. Unrelated warnings may already be present; compare against a build from before the edit if in doubt.

## 14. Publishing

PubSys builds the site; it doesn't publish it. On the family blogs, publishing means committing the site folder to its GitHub repository and pushing it. Cloudflare Pages then puts the contents of `html/` online automatically, usually within a minute or two. Each site's own instructions say how that's done there.

## 15. What PainScience.com's version adds

PubSys started as the blog engine for PainScience.com, which runs a much larger version with features that **don't work on the family blogs**. If one of these comes up, the honest answer is "not on this site"; Paul could bring a feature over if it matters.

- Citations and bibliography references. On PainScience.com `<<…>>` is a citation; on the blogs it's an image (§7).
- PainScience.com's own footnote system. The blogs use Markdown footnotes instead (§6), which some sites' templates show as pop-ups.
- Pull quotes (`<pq>`).
- Member-only and paywalled content (`<!-- === PAYWALL === -->`: don't use it on the blogs).
- Podcast audio attached to posts.
- Post ID numbers (`psid…` header lines), which would break a blog build.
- The `img()` image function, "related reading" boxes, and search-engine markup.
